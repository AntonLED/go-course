# 06. Статика из embed с ETag и 304

Пакет `static`. Урок: [Шаблоны и статические файлы](../../lessons/04-templates-static.md).

Раздача CSS, картинок и JS кажется скучной задачей, но именно от неё зависит, будет ли браузер при каждом заходе заново скачивать мегабайты статики. Правильные заголовки кэширования и ETag позволяют серверу ответить коротким `304 Not Modified`, когда у клиента уже есть актуальная копия. Кроме того, файловый сервер — классическое место для уязвимостей вроде выдачи `.env` наружу.

Файл `assets.go` уже вшивает каталог `assets/` через `//go:embed` и отдаёт его как `fs.FS` (функция `Assets()`). Ваша задача — написать свой файловый сервер поверх любой `fs.FS` (в тестах используется `testing/fstest.MapFS`).

## Что сделать

```go
func FileServer(fsys fs.FS) (http.Handler, error)
```

- При создании сервер один раз обходит ФС через `fs.WalkDir`, читает файлы и считает для каждого сильный ETag из содержимого: `"` + hex(первые 8 байт sha256) + `"`. Одинаковое содержимое даёт одинаковый ETag.
- Поддерживаются только `GET` и `HEAD`. На остальные методы сервер отвечает `405` с заголовком `Allow: GET, HEAD`.
- URL-путь превращается в имя в ФС через `path.Clean` с отбрасыванием ведущего `/`, потому что `fs.FS` не принимает ни `/a`, ни `..`.
- Для `/` и каталогов (`/docs`, `/docs/`) отдаётся их `index.html`. Каталог без `index.html` даёт 404, листинг не показывается.
- Любой путь, в котором есть сегмент, начинающийся с точки (`.env`, `.git/config`), даёт 404.
- В ответе выставляется `ETag` и `Cache-Control`: `no-cache` для `.html` и `public, max-age=86400` для всего остального. Эти заголовки нужны и в ответе `304`: по RFC 9110 он содержит те же `ETag` и `Cache-Control`, что и 200.
- Сам ответ отдаётся через `http.ServeContent`. Он поставит `Content-Type` по расширению, обработает `If-None-Match` (список, `W/`, `*`) и ответит `304`, а также разберётся с `Range` и `HEAD`. Обратите внимание: ETag должен оказаться в заголовках до вызова `ServeContent`, иначе тот не сможет его сравнить.

## Подвохи

`http.FileServerFS` из стандартной библиотеки умеет почти всё, но показывает листинг каталогов и не ставит ETag.

`no-cache` вовсе не означает «не кэшировать». Это «кэшируй, но перед использованием ревалидируй», что как раз и нужно для ETag. Запрет кэширования записывается как `no-store`.

Для файлов с хэшем в имени (`app.3f9a.css`) обычно ставят `max-age=31536000, immutable`: их содержимое по такому имени никогда не изменится.
