# Урок 4. Работа со строками

## Что такое строка

Если вы пришли из Python 3 или Java, где строка — это последовательность символов, Go поначалу удивит. Здесь строка — **неизменяемая последовательность байт**, и ничего больше. Внутри она устроена как заголовок из двух полей, который на amd64 занимает 16 байт:

```go
type stringHeader struct {
	data unsafe.Pointer
	len  int // длина в байтах
}
```

Из такого устройства следует почти всё поведение строк. Копирование строки копирует только заголовок, поэтому оно дёшево при любой длине текста. Подстрока `s[i:j]` тоже не выделяет память: она создаёт новый заголовок, который смотрит на те же байты. У этого есть обратная сторона: маленькая подстрока держит в памяти всю исходную строку. Если нужна независимая копия, используйте `strings.Clone`.

Поскольку строки неизменяемы, присваивание `s[0] = 'x'` — ошибка компиляции. И ещё одна деталь: нулевое значение строки — `""`, строка не бывает `nil`.

![`"Привет"` — заголовок `(data, len 12)` над 12 неизменяемыми байтами UTF-8, по 2 байта на букву; подстрока `s[2:6]` — второй заголовок над теми же байтами, без копирования](img/string-header.svg)

Исходные файлы Go пишутся в UTF-8, поэтому строковые литералы обычно тоже содержат UTF-8. Но **язык этого не гарантирует**. В строке могут лежать произвольные байты, например `"\xff"`, и код, работающий со строками из внешнего мира, должен быть к этому готов.

## byte и rune

Для работы с содержимым строк в Go есть два типа. `byte` — это синоним `uint8`, один байт. `rune` — синоним `int32`, и в нём хранится одна кодовая точка Unicode. Разница хорошо видна на литералах: `'я'` в одинарных кавычках — рунная константа со значением 1103, а `"я"` в двойных — строка длиной 2 байта.

```go
s := "Привет"
len(s)                       // 12 — байты!
utf8.RuneCountInString(s)    // 6 — символы
s[0]                         // 208 (0xD0) — первый байт буквы П
string(s[0])                 // "Ð" — байт 0xD0 как руна U+00D0
```

Этот пример стоит разобрать построчно. `len` считает байты, а не символы, поэтому для шести кириллических букв получается 12. Символы, то есть руны, считает `utf8.RuneCountInString`. Индексация `s[0]` возвращает байт, и это лишь первая половина буквы «П». А если превратить этот байт обратно в строку, Go поймёт его как руну с кодом U+00D0 и выдаст совсем другой символ, «Ð».

### UTF-8 кратко

UTF-8 кодирует символ от одного до четырёх байт в зависимости от его номера:

| Диапазон | Байт | Пример |
|---|---|---|
| U+0000–U+007F | 1 | ASCII `a` |
| U+0080–U+07FF | 2 | кириллица `я` |
| U+0800–U+FFFF | 3 | `世`, `€` |
| U+10000–U+10FFFF | 4 | эмодзи `🦔` |

Раз длина символа переменная, получить $i$-й символ строки за $O(1)$ нельзя: до него придётся дойти, декодируя всё, что стоит раньше. Для низкоуровневой работы с кодировкой есть пакет `unicode/utf8` с функциями `DecodeRuneInString`, `RuneLen`, `ValidString`, `EncodeRune` и константой `utf8.RuneError` (U+FFFD), которой обозначают некорректные байты.

## range по строке

Цикл `range` по строке, в отличие от индексации, работает с символами:

```go
for i, r := range "aя€" {
	fmt.Println(i, string(r))
}
// 0 a
// 1 я
// 3 €
```

![`"aя€"` занимает 6 байт: `a` — 1, `я` — 2, `€` — 3; `range` декодирует руны и выдаёт байтовые индексы их начала: 0, 1, 3](img/range-string.svg)

`range` **декодирует UTF-8** на ходу: в `r` попадает руна, а `i` — это **байтовый** индекс её начала. Поэтому индексы идут не подряд, как видно по выводу. Если по пути встретится некорректный байт, `r` окажется равна `utf8.RuneError` (U+FFFD), а обход сдвинется ровно на один байт и продолжится. Когда же нужен именно побайтовый обход, пишут обычный цикл по индексу: `for i := 0; i < len(s); i++ { s[i] }`.

## Конвертации

Строку можно превратить в срез байт или рун и обратно:

```go
b := []byte(s)   // копия байт (аллокация)
s2 := string(b)  // копия обратно (аллокация)
r := []rune(s)   // декодирование, 4 байта на символ
s3 := string(r)  // кодирование в UTF-8
string(rune(65)) // "A"
strconv.Itoa(65) // "65"
```

Каждая конвертация между `string` и `[]byte` в общем случае **копирует данные**. Иначе и быть не может: срез байт можно менять, и если бы он разделял память со строкой, неизменяемость строки была бы нарушена. Компилятор, впрочем, умеет обходиться без копии в частных случаях, когда он уверен, что никто ничего не изменит: при поиске в map через `m[string(b)]`, при сравнении `string(b) == "x"`, в цикле `for range []byte(s)` и при конкатенации во временную строку.

![`[]byte(s)` выделяет новый изменяемый массив и копирует байты, поэтому `b[0] = 'H'` не трогает `s`; `string(b)` снова копирует, уже в новую неизменяемую строку](img/string-bytes-copy.svg)

Отсюда понятно, почему разворот строки через `[]byte` ломает многобайтовые символы: переставляются половинки букв. Правильно разворачивать через `[]rune`. Но и это решение не идеально. Буква «й» может быть записана двумя кодовыми точками, `и` и комбинируемым знаком U+0306, а составные эмодзи состоят из нескольких рун. Чтобы корректно работать с ними, нужен уровень графем, а его в стандартной библиотеке нет.

## Конкатенация и аллокации

Вот код, который выглядит невинно, но на большом объёме данных работает удручающе медленно:

```go
s := ""
for _, w := range words {
	s += w // каждый раз новая строка: O(n²) копирования
}
```

Строки неизменяемы, поэтому каждое `+=` создаёт новую строку и копирует в неё всё, что накопилось раньше. В сумме это $O(n^2)$ копирования. Правильный инструмент — `strings.Builder`:

```go
var b strings.Builder
b.Grow(estimated) // опционально — одна аллокация
for _, w := range words {
	b.WriteString(w)
}
res := b.String() // без копирования: Builder отдаёт свой буфер
```

![`s += w` на каждом шаге создаёт новую строку и копирует всё накопленное; `strings.Builder` дописывает в один буфер, а `String()` отдаёт строку над ним без копии](img/concat-vs-builder.svg)

У `strings.Builder` есть одно ограничение: его нельзя копировать после начала использования. Скопированный билдер при записи паникует с сообщением «illegal use of non-zero Builder copied by value».

Есть и другие способы собрать строку, и у каждого своя ниша. `strings.Join(words, ", ")` заранее считает итоговую длину и обходится одной аллокацией, так что для склейки готового списка это лучший выбор. `fmt.Sprintf` удобен, но медленнее, потому что работает через интерфейсы и рефлексию. `bytes.Buffer` пригодится, когда объект должен быть одновременно `io.Reader` и `io.Writer`. А выражение вида `a + b + c` компилятор склеивает сам за одну аллокацию, так что бояться простого `+` вне цикла не нужно.

## Пакет strings — основное

Самые ходовые функции пакета `strings` собраны ниже. Обратите внимание на комментарии: в нескольких местах поведение отличается от того, что подсказывает интуиция.

```go
strings.Contains(s, "go"); strings.HasPrefix/HasSuffix
strings.Index(s, "x")            // байтовый индекс или -1
strings.Split("a,b,,c", ",")     // ["a" "b" "" "c"]
strings.Fields("  a  b ")        // ["a" "b"] — по пробельным символам
strings.TrimSpace, Trim(s, "xy"), TrimPrefix, TrimSuffix
strings.TrimLeft("xxabc", "xa")  // "bc" — набор символов, не префикс!
strings.ToLower / ToUpper        // Unicode-aware
strings.EqualFold("Go", "GO")    // сравнение без регистра без аллокаций
strings.Repeat, Replace, ReplaceAll
strings.Map(func(r rune) rune {...}, s) // -1 — удалить символ
strings.Cut("k=v", "=")          // "k", "v", true (Go 1.18)
strings.NewReplacer("a", "1", "b", "2").Replace(s)
```

Для классификации отдельных рун есть пакет `unicode`: `IsLetter`, `IsDigit`, `IsSpace`, `IsUpper`, `ToLower` и `In(r, unicode.Cyrillic)` для проверки принадлежности к письменности.

## strconv

Переводом между строками и числами занимается пакет `strconv`:

```go
n, err := strconv.Atoi("42")          // ошибка *strconv.NumError
i, err := strconv.ParseInt("ff", 16, 64)
f, err := strconv.ParseFloat("3.14", 64)
b, err := strconv.ParseBool("true")
strconv.Itoa(42); strconv.FormatInt(255, 2) // "11111111"
strconv.Quote("привет\n")             // "\"привет\\n\""
strconv.AppendInt(buf, 42, 10)        // без аллокации строки
```

Парсеры в `strconv` строгие. `Atoi("  42")` вернёт ошибку, потому что пробелы не обрезаются, их нужно убрать заранее. При этом знак плюс допустим: `Atoi("+42")` сработает.

## Сравнение строк

Операторы `==`, `<` и `>` сравнивают строки **побайтово**, то есть лексикографически по их UTF-8 представлению. Для латиницы это совпадает с алфавитным порядком, а вот для других языков даёт странные результаты. Латиница всегда оказывается меньше кириллицы, заглавная `"Я"` меньше строчной `"а"`, а `"ё"` больше `"я"`, потому что кодовая точка U+0451 стоит после U+044F. Для «человеческой» сортировки с учётом правил языка нужен collation, например из пакета `golang.org/x/text/collate`.

## Сырые строки

Строку можно записать в обратных кавычках. Внутри такого литерала экранирование не работает, и он может занимать несколько строк, что особенно удобно для путей Windows и регулярных выражений:

```go
path := `C:\dir\file`   // без экранирования, может быть многострочной
re := `^\d+$`
```
