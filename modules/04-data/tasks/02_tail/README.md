# Задача 02. `tail -n` по `io.ReadSeeker`

Когда нужно посмотреть последние строки многогигабайтного лога, `tail` не читает файл с начала — он прыгает в конец и движется назад. Именно этот приём мы и реализуем. Задача хорошо показывает, зачем в Go есть `io.Seeker` и почему работа с блоками на границах всегда сложнее, чем кажется.

Пакет называется `tail`, реализовать нужно в `tail.go`:

```go
func Tail(rs io.ReadSeeker, n int) ([]string, error)
```

Функция возвращает последние `n` строк потока без `\n` (и без завершающего `\r`, если строки в формате CRLF). Требования такие:

- Читайте с конца, блоками по `ChunkSize` (константа в `types.go`), через `rs.Seek(pos, io.SeekStart)` и `io.ReadFull`. Тест читает хвост файла размером 1.2 МБ и проверяет, что прочитано не больше `4*ChunkSize` байт.
- Завершающий `\n` не порождает пустую строку: для `"1\n2\n"` последние 2 строки — это `["1" "2"]`. Но `"a\n\n\n"` состоит из строк `a`, `""`, `""`.
- Текущая позиция `rs` на входе может быть любой.
- При `n == 0` или пустом потоке результат имеет длину 0; при `n < 0` функция возвращает `ErrNegative`.
- Функция должна работать и с `*os.File`, и с `*strings.Reader`: оба реализуют `io.ReadSeeker`.

## Подвохи

Строка может оказаться длиннее блока (в тестах есть строка на 10 000 байт), поэтому нельзя рассчитывать, что в каждом блоке найдётся `\n`. Первая «строка» очередного блока почти всегда обрезана слева, и возвращать её можно, только когда вы дошли до начала файла. Отдельно проверьте случай, когда `\n` лежит ровно на границе блока.

И помните, что `Read` может вернуть меньше байт, чем вы просили. Поэтому здесь нужен `io.ReadFull`, а не голый `Read`.
