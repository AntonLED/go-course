# Задача 08. Мини-YAML: парсер подмножества в `map[string]any`

YAML — формат конфигов Kubernetes, CI-пайплайнов и docker-compose. Выглядит он просто, но за этой простотой прячется немало ловушек: `no` иногда превращается в `false`, а версия `1.10` — в число `1.1`. Лучший способ понять формат — написать для него парсер, пусть и для подмножества.

Пакет `miniyaml`. Реализуйте в `miniyaml.go`:

```go
func Parse(src string) (map[string]any, error)
```

В реальных проектах YAML читают через `gopkg.in/yaml.v3`, но в курсе внешних зависимостей нет. Наша цель — разобраться, как устроен формат, и заодно наступить на его известные грабли.

## Что поддерживать

```yaml
# комментарий; '---' в первой строке игнорируется
name: billing
port: 8080              # int
ratio: 0.75             # float64
debug: false            # bool: true/True/TRUE/false/False/FALSE
country: no             # string! (YAML 1.2; в YAML 1.1 это был бы false)
version: 1.10           # float64 1.1 — классическая ловушка
version_str: "1.10"     # string
empty:                  # nil (также null, Null, NULL, ~)
url: http://x.io/a#frag # ':' и '#' без пробела — часть значения
quote: 'it''s'          # одинарные кавычки: '' → '
escaped: "a\tb \"q\""   # двойные: экранирование как в Go (strconv.Unquote)
db:                     # вложенность — отступами из пробелов (любой ширины, но единообразно в блоке)
  host: localhost
tags:                   # список
  - api
  - "42"                # строка
features: [auth, "b, c", 3]   # flow-список скаляров; [] — пустой список; {} — пустая map
servers:                # список на том же отступе, что и ключ, — тоже валиден
- name: a               # элемент-отображение: ключи выровнены по первому ключу
  weight: 1
matrix:
  -                     # "-" и вложенный блок ниже
    - 1
```

Результат строится из типов `map[string]any`, `[]any`, `string`, `int`, `float64`, `bool` и `nil`. Для пустого документа возвращается пустая, но не nil, map.

Скаляры без кавычек типизируются по правилам YAML 1.2 core schema:

- null — `null`/`Null`/`NULL`/`~`/пусто;
- bool — `true`/`True`/`TRUE`/`false`/`False`/`FALSE`;
- int — `[-+]?[0-9]+`, а также `0o[0-7]+` (восьмеричное) и `0x[0-9a-fA-F]+` (шестнадцатеричное, без знака);
- float — десятичная запись `[-+]?(\.[0-9]+|[0-9]+(\.[0-9]*)?)([eE][-+]?[0-9]+)?` (`3.14`, `-.5`, `1.`, `2E-2`, `1e3`), `[-+]?.inf` (также `.Inf`, `.INF`) и `.nan` (также `.NaN`, `.NAN`);
- string — всё остальное, в том числе то, что `strconv` понимает сверх этого (`Inf`, `NaN`, `-0x1F`, `0b101`, `1_000`, `0x1p-2`).

Два уточнения. Ведущий ноль (`0777`) не делает число восьмеричным: это обычное десятичное целое 777, а восьмеричная запись без `o` существовала только в YAML 1.1. Целое, которое не влезает в int, становится float64.

## Ошибки (текст должен содержать «строка N»)

Номер строки в сообщении нужен, чтобы человек сразу нашёл место ошибки в своём конфиге. Ошибкой считаются:

- табуляция в отступе;
- повторяющийся ключ;
- неожиданный отступ;
- корень документа — список;
- строка без `ключ:`;
- смешение ключей и элементов списка на одном уровне;
- незакрытые кавычки и скобки.

Отдельная группа — конструкции, на которые парсер отвечает «не поддерживается»: якоря `&a`/`*a`, теги `!!str`, многострочные `|`/`>`, непустые flow-map `{a: 1}`, вложенные flow-коллекции и `- - x`.

## Подсказки

Начните с того, чтобы превратить текст в `[]line{num, indent, text}`: уберите комментарии (`#` в начале строки или после пробела, причём вне кавычек), пустые строки и хвостовые пробелы. Дальше работать с такой структурой гораздо проще, чем с сырым текстом.

Сам разбор удобно писать рекурсивным спуском. `parseMap(indent)` читает строки ровно с этим отступом; если после `key:` следующая строка оказалась глубже, вызываем рекурсивно `parseNode(её отступ)`.

Запись `- key: v` — это отображение, ключи которого стоят на колонке `key`. Можно «переписать» текущую строку как `key: v` с отступом `indent+2` и вызвать `parseMap`.
