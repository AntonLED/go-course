# Задание 4. `importer`: импорт CSV / JSON Lines в SQL с отчётом

Выгрузку товаров из Excel или из чужой системы рано или поздно приходится загружать в свою базу. Файл при этом всегда немного «грязный»: BOM в начале, лишние колонки, цены с тремя знаками после точки, дубликаты артикулов. Хороший импортёр не падает на первой же кривой строке. Он загружает всё, что можно, и выдаёт понятный отчёт о том, что пришлось пропустить.

Это итоговое задание модуля, и в нём сходится всё пройденное: потоки и gzip, флаги и коды возврата, файлы, CSV и JSON, `database/sql` и транзакции.

Пакет `importer`. Константы, `Schema`, `Product`, `Report` и `RecordError` лежат в `types.go`, реализовать нужно в `importer.go`:

```go
func Run(args []string, stdin io.Reader, stdout, stderr io.Writer) int
```

Эта функция и есть вся CLI-утилита. Её `main` состоит из одной строки `os.Exit(importer.Run(os.Args[1:], os.Stdin, os.Stdout, os.Stderr))`, а тесты вызывают `Run` напрямую, без запуска процесса.

```
usage: importer -db DSN [-format csv|jsonl] [-dry-run] [-strict] [FILE]
```

## Аргументы

- `-db DSN` обязателен. База открывается через `sql.Open("memsql", dsn)` (с пустым импортом `_ "gocourse/modules/04-data/memsql"`), таблица создаётся запросом `Schema` (`IF NOT EXISTS`).
- `FILE` можно указать не больше одного. Если его нет или указан `-`, данные читаются из stdin.
- `-format` принимает `csv` или `jsonl`. Если флаг не задан, формат определяется по расширению файла без учёта регистра: `.csv`, `.jsonl` или `.ndjson`, с возможным `.gz` на конце (`items.jsonl.gz`). Если определить формат не удалось, это ошибка использования.
- Сжатие gzip определяется по магическим байтам `1f 8b` (через `bufio.Reader.Peek(2)`), в том числе для stdin.
- `-dry-run` означает «всё проверить и посчитать, но не коммитить»; в отчёте при этом стоит `"dry_run": true`.
- `-strict` означает, что при хотя бы одной невалидной записи в базу не пишется ничего (`inserted` и `updated` равны 0), а код возврата — 1.

## Форматы

В CSV первая строка — заголовок. Имена колонок сравниваются без учёта регистра и пробелов, порядок колонок любой, лишние колонки игнорируются. Обязательны колонки `sku,name,price,qty`, необязательна `category`. В начале файла может стоять BOM (`﻿`) — так сохраняет Excel. Номер строки записи берётся из `csv.Reader.FieldPos(0)`, потому что поле в кавычках может занимать несколько строк. Запись с неверным числом полей считается невалидной записью. А вот пустой ввод, отсутствие обязательной колонки, повтор колонки в заголовке и синтаксическая ошибка CSV — фатальные ошибки.

В JSON Lines на каждой строке один объект, пустые строки пропускаются, длина строки не ограничена. Пример записи: `{"sku":"A-1","name":"Ручка","price":12.34,"qty":1,"category":null}`. Поля `price` и `qty` могут быть как числом, так и строкой (`json.Number`). Неизвестные поля, синтаксическая ошибка и два объекта в одной строке делают запись невалидной, но импорт не прерывают.

## Валидация записи

| Поле | Правило |
|---|---|
| `sku` | после `TrimSpace` непустой, не длиннее 32 символов, только `[A-Za-z0-9_-]`; повтор sku во входных данных — ошибка (первое вхождение принимается) |
| `name` | после `TrimSpace` непустое (сохраняется обрезанным) |
| `price` | `12`, `12.5`, `12.50` переводятся в центы (`int64`) без float (`0.29*100 = 28.999…`); не больше 2 знаков после точки, без знака, экспоненты и запятой |
| `qty` | целое, не меньше 0 |
| `category` | необязательное; пустое записывается как `NULL` |

## Запись в базу

Весь импорт идёт в одной транзакции: один `BeginTx` и сразу `defer tx.Rollback()`. Каждая валидная запись сохраняется как upsert: если такой sku уже есть в базе, выполняется `UPDATE` (и запись считается в `updated`), иначе `INSERT` (считается в `inserted`). Оформите это как маленький репозиторий поверх `*sql.Tx`. Ошибка базы данных фатальна, и транзакция откатывается.

## Вывод и коды возврата

Отчёт печатается в stdout через `json.Encoder` с `SetIndent("", "  ")`:

```json
{
  "total": 12,
  "inserted": 2,
  "updated": 0,
  "skipped": 10,
  "dry_run": false,
  "errors": [
    {"line": 2, "error": "sku: обязательное поле"},
    {"line": 9, "sku": "ok-1", "error": "sku: дубликат (впервые в строке 1)"}
  ]
}
```

Поле `errors` всегда массив: `[]`, а не `null`.

Коды возврата:

- `0` — всё прошло успешно; тот же код у `-h`.
- `3` — импорт выполнен, но часть записей пропущена.
- `1` — фатальная ошибка (сообщение в stderr, stdout пуст) или `-strict` при наличии ошибок (отчёт в stdout, сообщение в stderr).
- `2` — ошибка в аргументах (usage в stderr, stdout пуст).

## Подвохи

Из-за BOM первая колонка заголовка CSV называется не `sku`, а `"﻿sku"`. Поскольку `"﻿sku" != "sku"`, колонка не найдётся, если BOM не срезать.

В CSV бывают многострочные поля, поэтому номер записи не совпадает с номером строки файла.

`bufio.Scanner` без увеличенного `Buffer` упадёт на строке JSONL длиннее 64 КиБ.

Если декодировать цену через `json.Unmarshal` в `float64`, вы потеряете точность. `json.Number` хранит исходный текст числа, и с ним можно работать без округлений.

Режимы `-dry-run` и `-strict` на деле означают просто «не вызывать Commit», а остальное сделает `defer tx.Rollback()`.

Внутри транзакции все запросы идут через `tx`, а не через `db`.
