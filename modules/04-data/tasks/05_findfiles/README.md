# Задача 05. `find` и `tree` поверх `fs.FS`

Обход дерева файлов нужен постоянно: найти все `*.go`, собрать статику, показать структуру проекта. Если писать такой код прямо поверх `os`, его трудно тестировать и нельзя переиспользовать для архивов или встроенных файлов. Интерфейс `fs.FS` решает обе проблемы, и в этой задаче мы напишем на нём упрощённые `find` и `tree`.

Пакет `findfiles`. Типы `Options` и `File` лежат в `types.go`, реализовать нужно в `findfiles.go`:

```go
func Find(fsys fs.FS, root string, opt Options) ([]File, error)
func Tree(fsys fs.FS, root string) (string, error)
```

Функции принимают абстрактную `fs.FS`, поэтому работают с `os.DirFS(dir)`, `embed.FS`, zip-архивом (`zip.Reader`) и тестовой `fstest.MapFS`. Тесты вообще не трогают диск, за исключением одного, который использует `t.TempDir()`.

## Find

- Возвращаются только обычные файлы (`d.Type().IsRegular()`), без каталогов и симлинков, в порядке обхода `fs.WalkDir`, то есть лексикографически внутри каждого каталога.
- `Pattern` — это glob по имени файла. Используйте `path.Match`, а не `filepath.Match`: в `fs.FS` разделитель всегда `/`.
- `MinSize` проверяется включительно. Размер берётся из `d.Info()`, и вызывать его стоит только после дешёвых фильтров.
- `MaxDepth` ограничивает глубину: `1` — только файлы прямо в `root`, `2` — ещё уровень ниже, `0` — без ограничения. В слишком глубокие каталоги мы не заходим вовсе (`fs.SkipDir`).
- При `SkipHidden` файлы с именами на `.` пропускаются, а в скрытые каталоги мы не заходим. Сам `root` не пропускается, даже если он скрытый (например, `.git`).
- Функция возвращает ошибку в трёх случаях: невалидный `root` (по `fs.ValidPath`: абсолютный, с `..`, с завершающим `/`, пустой), несуществующий `root` (`errors.Is(err, fs.ErrNotExist)`) и плохой шаблон (`errors.Is(err, path.ErrBadPattern)`). Плохой шаблон — ошибка даже тогда, когда в FS нет ни одного файла.

## Tree

```
.
├── a.txt
├── dir
│   ├── b.txt
│   └── sub
│       └── c.txt
└── z.go
```

Первая строка — `root` как есть. Порядок элементов — как у `fs.ReadDir`, то есть по имени. Каждая строка, включая последнюю, заканчивается `\n`.

## Подвохи

Возврат `fs.SkipDir` из колбэка на файле пропускает все оставшиеся файлы этого каталога, а для фильтрации это совсем не то, что нужно.

Колбэк `WalkDir` может получить `err != nil`, например для несуществующего `root`, и такую ошибку нельзя игнорировать.

Глубина считается относительно `root`, а не от корня FS.
