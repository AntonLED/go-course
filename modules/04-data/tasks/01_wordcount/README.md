# Задача 01. wc на потоках: `Count(io.Reader)`

Утилиту `wc` знает каждый, кто работал в терминале: она считает строки, слова и байты во входном потоке. Мы напишем её ядро на Go, и главный урок здесь не в подсчёте, а в работе с `io.Reader`. Данные приходят кусками произвольного размера, файл может оказаться огромным, а чтение — оборваться с ошибкой. Хорошая реализация переживает всё это и не читает поток в память целиком.

Работаем в пакете `wordcount`. Тип `Counts` уже объявлен в `types.go`, а функцию нужно реализовать в `wordcount.go`:

```go
func Count(r io.Reader) (Counts, error)
```

Поля результата означают следующее:

| Поле | Смысл |
|---|---|
| `Lines` | число строк; последняя строка без `\n` тоже считается; пустой ввод — 0 строк, `"\n"` — 1 |
| `Words` | число слов; разделитель — любая руна, для которой `unicode.IsSpace` (включая ` `, `　`) |
| `Bytes` | число байт |
| `Runes` | число рун; невалидный байт UTF-8 считается одной руной (как `utf8.RuneCount`) |
| `MaxLineLen` | длина самой длинной строки в рунах, без `\n` и без завершающего `\r` (CRLF) |

Например, `Count(strings.NewReader("a b\nccc\n"))` должна вернуть `{Lines:2 Words:3 Bytes:8 Runes:8 MaxLineLen:3}`.

## Подвохи

- В тестах есть строка длиной около 600 КиБ. `bufio.Scanner` с настройками по умолчанию на ней вернёт `bufio.ErrTooLong`, потому что лимит токена — 64 КиБ. Либо увеличьте буфер через `scanner.Buffer(buf, max)`, либо читайте через `bufio.Reader`.
- Тест прогоняет ввод через `iotest.OneByteReader`. Reader имеет право отдавать данные кусками любого размера, в том числе разрезая многобайтовую руну или слово посередине, и ваш код должен это выдерживать.
- Если `Read` вернул ошибку, отличную от `io.EOF`, верните её вместе с уже посчитанными к этому моменту значениями.
- Символ `\r` учитывается в длине строки, только если за ним не идёт `\n`.
