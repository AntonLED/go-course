# Модуль 4. Работа с данными

Любая полезная программа принимает данные извне и куда-то их отдаёт: читает файлы и сетевые потоки, разбирает аргументы командной строки, декодирует JSON и YAML, ходит в базу данных. Этот модуль как раз про такие «границы» программы — потоки ввода/вывода, CLI, файлы, JSON и YAML, SQL. В конце вас ждёт утилита импорта, в которой все эти темы собираются вместе.

## Цели

К концу модуля вы будете:

- уверенно комбинировать `io.Reader` и `io.Writer`, знать контракты `Read` и `Write`, возможности `bufio` и его подводные камни;
- писать CLI на `flag.FlagSet` со своими типами флагов и подкомандами и тестировать его, не запуская процесс;
- безопасно работать с файлами (не терять ошибки `Close`, записывать атомарно) и абстрагироваться от диска через `fs.FS`;
- знать тонкости `encoding/json` (теги, свои маршалеры, полиморфизм, потоковый разбор) и грабли YAML;
- писать корректный код на `database/sql`: с пулом, контекстом, `NULL`, транзакциями, плейсхолдерами и доменными ошибками.

## Учебный SQL-драйвер `memsql`

Внешние зависимости в курсе недоступны, поэтому настоящую СУБД для уроков и задач по SQL подключить нельзя. Вместо неё написан драйвер [`memsql`](memsql) — база данных в памяти, которая реализует интерфейсы `database/sql/driver`: `Driver`, `Conn`, `Stmt`, `Tx`, `Rows`, а также `ConnBeginTx`, `ExecerContext`, `QueryerContext` и `Pinger`. Для вашего кода он неотличим от настоящего драйвера и так же регистрируется в `init`:

```go
import (
    "database/sql"
    _ "gocourse/modules/04-data/memsql"
)

db, err := sql.Open("memsql", "testdb1") // один DSN — одна общая база; разные DSN — разные базы
```

Все подключения с одним и тем же DSN видят одну общую базу. Чтобы тесты не мешали друг другу, удобно давать каждому уникальное имя: `dsn := memsql.NewDSN(t.Name())` и `defer memsql.Drop(dsn)`.

### Что поддерживается

memsql понимает небольшое, но достаточное для практики подмножество SQL:

```sql
CREATE TABLE [IF NOT EXISTS] t (col TYPE [PRIMARY KEY] [NOT NULL] [UNIQUE], ...)
DROP TABLE [IF EXISTS] t
INSERT INTO t [(a, b)] VALUES (?, ?)[, (?, ?) ...]
SELECT a, b | * | COUNT(*) FROM t [WHERE cond [AND cond ...]] [ORDER BY col [ASC|DESC], ...] [LIMIT n] [OFFSET n]
UPDATE t SET a = expr, b = expr [WHERE ...]
DELETE FROM t [WHERE ...]
```

Условие `cond` — это сравнение `col = | != | <> | < | <= | > | >= expr` или проверка `col IS [NOT] NULL`. Условия соединяются только через `AND`, `OR` не поддерживается. Выражение `expr` — это плейсхолдер `?` или `$N`, литерал (`42`, `1.5`, `'it''s'`, `TRUE`, `FALSE`, `NULL`), имя колонки или сумма и разность двух операндов (`операнд + операнд`, `операнд - операнд`), например `balance - ?`.

Типы колонок отображаются на типы Go так:

| SQL | Go |
|---|---|
| `INTEGER`, `INT`, `BIGINT` | `int64` |
| `TEXT`, `VARCHAR(n)` | `string` |
| `REAL`, `FLOAT`, `DOUBLE` | `float64` |
| `BOOLEAN` | `bool` |
| `TIMESTAMP` | `time.Time` |

`NULL` допустим в любой колонке без `NOT NULL`, а значение несовместимого типа вызывает ошибку. Колонка `INTEGER PRIMARY KEY`, для которой значение не передано, получает $\max + 1$ (как rowid в SQLite), и этот идентификатор возвращается через `Result.LastInsertId()`.

Семантика соответствует обычному SQL: сравнение с `NULL` никогда не бывает истинным, а в `ORDER BY` при `ASC` значения `NULL` идут первыми.

Ограничения проверяются по-настоящему. Нарушение `PRIMARY KEY` или `UNIQUE` возвращает `memsql.ErrUniqueViolation`, нарушение `NOT NULL` — `memsql.ErrNotNullViolation`, и проверять их нужно через `errors.Is`. Каждый оператор атомарен: многострочный `INSERT`, в котором встретился дубль, не оставит в таблице частичных данных.

Транзакции устроены через снимки. `BeginTx` делает снимок таблиц, и это дёшево, потому что таблицы неизменяемы, а запись идёт по принципу copy-on-write. До `Commit` изменения видны только внутри транзакции, а `Rollback` их просто выбрасывает. Транзакции одной базы сериализуются: вторая `BeginTx` ждёт, пока завершится первая, или пока не отменят контекст. Если таблицу, изменённую в транзакции, параллельно поменял запрос вне транзакции, `Commit` вернёт `memsql.ErrSerialization`. Транзакция с `ReadOnly` запрещает запись.

Контекст тоже учитывается: если `ctx` уже отменён, запрос вернёт `context.Canceled`, не начав выполняться.

Тесты самого драйвера запускаются командой `go test -race ./modules/04-data/memsql/`.

### В реальной жизни

В продакшене на месте memsql окажется PostgreSQL с драйвером `github.com/jackc/pgx/v5` (для `database/sql` — через `pgx/v5/stdlib`). Приятная новость в том, что **код репозиториев останется тем же**: `sql.DB`, `QueryRowContext`, `Scan`, `sql.ErrNoRows`, `BeginTx`/`Commit`/`Rollback`, `sql.Null*`. Отличия сосредоточены в нескольких местах:

- DSN выглядит так: `sql.Open("pgx", "postgres://user:pass@host:5432/db?sslmode=disable")`;
- плейсхолдеры записываются как `$1, $2` (memsql понимает и их);
- ID новой строки получают через `INSERT ... RETURNING id` и `QueryRowContext(...).Scan(&id)`, а не через `LastInsertId`;
- ошибка нарушения ограничения приходит как `*pgconn.PgError` с кодом `23505` вместо `memsql.ErrUniqueViolation`;
- upsert пишется как `INSERT ... ON CONFLICT (key) DO UPDATE`;
- появляются настоящая изоляция и блокировки (`SELECT ... FOR UPDATE`), а для интеграционных тестов понадобятся testcontainers или отдельная тестовая база;
- в PostgreSQL любая ошибка внутри транзакции (например, нарушение `UNIQUE`) переводит её в состояние aborted, и все дальнейшие запросы в ней отклоняются до `ROLLBACK` (или отката к `SAVEPOINT`). В memsql ошибочный оператор просто не применяется, а транзакция продолжает работать.

## Как проверять

Решения проверяются тестами. Запускайте их из корня курса:

```
cd go-course  # корень курса
go test ./modules/04-data/tasks/01_wordcount/                  # ваше решение
go test -tags solution ./modules/04-data/tasks/01_wordcount/   # эталон
go test -race ./modules/04-data/...                            # всё, с детектором гонок
go vet ./modules/04-data/...
```

Заготовки задач компилируются, но тесты на них падают. Так и задумано: тесты станут зелёными, когда задача будет решена.
