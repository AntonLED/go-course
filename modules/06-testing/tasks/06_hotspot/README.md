# 06. Найти и устранить горячие точки

Пакет `hotspot`. Урок: [Профилирование](../../lessons/04-profiling.md).

Три функции в `hotspot.go` написаны «в лоб». На маленьких данных всё хорошо и тесты на корректность зелёные, а на 200 тысячах строк эти функции работают минутами. Такое регулярно случается в реальных проектах: код годами живёт на тестовых данных, а потом приходит крупный клиент. Тесты `*Fast` дают каждой функции по 3 секунды, при том что линейное решение укладывается в десятки миллисекунд, а под `-race` — в пару сотен.

```go
func Dedup(lines []string) []string                  // убрать повторы, сохранив порядок
func TopWords(text string, k int) []WordCount        // k самых частых слов
func Report(lines []string) string                   // "1: ...\n2: ...\n"
```

Поведение функций менять нельзя: оно проверяется против эталона на случайных входах. Это касается и сортировки в `TopWords` — по убыванию `Count`, а при равенстве по возрастанию `Word`, — и того, что при `k <= 0` возвращается пустой, но не `nil` срез.

## Как искать

Не угадывайте, а измеряйте:

```
go test -run XXX -bench TopWords -cpuprofile cpu.out ./modules/06-testing/tasks/06_hotspot/
go tool pprof -top cpu.out               # плоский топ функций
go tool pprof -list TopWords cpu.out     # построчно: где именно время
go tool pprof -http=:8080 cpu.out        # flame graph в браузере
go test -run XXX -bench . -benchmem ./modules/06-testing/tasks/06_hotspot/   # аллокации
```

Что вы, скорее всего, увидите в профиле? Если наверху `runtime.memmove` и `runtime.concatstrings`, виновата конкатенация `+=` в цикле, которая обходится в $O(n^2)$ по байтам. Линейный поиск по срезу внутри цикла (`slices.Contains`) даёт те же $O(n^2)$. Встречаются и пузырьковая сортировка, и посимвольная сборка строк.

## Запуск проверки

```
go test -race ./modules/06-testing/tasks/06_hotspot/
```
