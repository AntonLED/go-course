# Модуль 3. Параллельное программирование

Конкурентность — то, ради чего Go часто и выбирают, и то, на чём чаще всего спотыкаются. Писать `go f()` умеют все, а вот объяснить, почему программа зависла, почему в ней течёт память или почему восемь ядер дали ускорение всего вдвое, получается далеко не у каждого. Этот модуль проходит путь от устройства планировщика до готовых инструментов вроде `errgroup` и `singleflight`: горутины, модель памяти, примитивы синхронизации, каналы и паттерны на них, контекст.

К концу модуля вы сможете:

- объяснить, как устроен планировщик Go (G, M, P, work stealing, netpoller, вытеснение), и заранее оценить пользу от параллелизма по закону Амдала;
- писать конкурентный код без гонок и утечек горутин и проверять это флагом `-race` и тестами;
- осознанно выбирать между каналами, мьютексами и атомиками, опираясь на отношение happens-before;
- строить конвейеры, fan-in/fan-out, пулы воркеров, семафоры и rate limiter;
- правильно использовать `context` для отмены, таймаутов и request-scoped значений;
- применять `errgroup` и `singleflight` и реализовать их самостоятельно.

## Как проверять

В каждой задаче заготовка лежит в `<name>.go` (с тегом `//go:build !solution`), а тесты — в `<name>_test.go`. Замените `panic("TODO")` своей реализацией и запустите тесты из корня репозитория:

```bash
# из корня репозитория
go test -race ./modules/03-concurrency/tasks/05_pipeline/
go test -race ./modules/03-concurrency/...            # все задачи модуля
go vet ./modules/03-concurrency/...                   # copylocks, lostcancel и др.
```

**Запускайте тесты с `-race` каждый раз**: половина задач проверяет именно отсутствие гонок, и без детектора они пройдут, даже если гонка в коде есть. Кроме того, тесты следят, чтобы после работы не оставалось «висящих» горутин (сравнивают `runtime.NumGoroutine` до и после), чтобы выходные каналы закрывались и чтобы заявленный параллелизм реально достигался.

Эталонные решения лежат в файлах `*_solution.go` с тегом `//go:build solution`. Заглядывайте в них после собственной попытки, а не вместо неё:

```bash
go test -race -tags solution ./modules/03-concurrency/...
```
