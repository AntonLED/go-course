# 01. Параллельная сумма по чанкам (`parsum`)

Урок: [Введение в параллельное программирование. Модель PMG](../../lessons/01-intro-pmg.md)

Сложить миллион чисел — задача, которую проще всего распараллелить: делим срез на куски, считаем каждый кусок в своей горутине и складываем частичные суммы. На ней удобно увидеть и выигрыш от параллельности, и её цену. Реализуйте в `parsum.go`:

```go
func Workers(n int) int                                   // n>0 ? n : runtime.GOMAXPROCS(0)
func Sum(nums []int64, workers int) int64                 // параллельная сумма
func Count[T any](items []T, workers int, pred func(T) bool) int
```

Требования:

- Срез делится на `k = min(Workers(workers), len(items))` непрерывных чанков почти равного размера (размеры отличаются не больше чем на 1 элемент), и на каждый чанк запускается ровно одна горутина.
- Для пустого или `nil` среза результат равен `0`, и горутины не запускаются.
- Одновременно выполняется не больше `Workers(workers)` вызовов `pred`, и они действительно выполняются параллельно: тест проверяет, что набирается ровно `workers` одновременно активных вызовов.
- Утечек горутин быть не должно: к моменту возврата из функции все воркеры завершены.
- Мьютекс для суммирования не используйте. Пусть каждая горутина пишет в свою ячейку среза `partial[i]`, а после `wg.Wait()` главная горутина сложит частичные суммы.

Пример:

```go
parsum.Sum([]int64{1, 2, 3, 4, 5}, 2)                          // 15 (чанки [1 2 3] и [4 5])
parsum.Count([]int{1, 2, 3, 4}, 0, func(x int) bool { return x > 2 }) // 2
```

## Подсказки и подвохи

Почему по умолчанию берётся `GOMAXPROCS`, а не `runtime.NumCPU()`? Go-код одновременно исполняют ровно `GOMAXPROCS` потоков, и это значение может быть меньше `NumCPU`. Его задают вручную через переменную окружения или с помощью `automaxprocs` в контейнере с CPU-квотой, а начиная с Go 1.25 рантайм сам учитывает квоту cgroup (в Go 1.23 по умолчанию `GOMAXPROCS == NumCPU`). Для CPU-bound работы воркеров больше, чем P, вычисления не ускорят.

Параллельность не бесплатна. Запуск горутины стоит порядка 1 мкс и 2–8 КБ стека, поэтому на маленьком срезе параллельная версия проигрывает последовательной. Убедитесь сами: `go test -bench . -tags solution`.

Писать в соседние ячейки `partial[i]` из разных горутин безопасно, потому что это разные переменные. Но если делать это в горячем цикле, возникнет false sharing: ячейки лежат в одной кэш-линии, и ядра будут постоянно отбирать её друг у друга. Поэтому копите сумму в локальной переменной и записывайте в `partial[i]` один раз в конце.
