# Задание 3. Конкурентный веб-краулер с кэшем (`crawler`)

Финальный проект модуля «Параллельное программирование». Краулер — классическая задача, на которой проверяют понимание конкурентности: страниц много, загружаются они медленно, ссылки образуют циклы, а пользователь в любой момент может нажать «стоп». Здесь вам понадобится всё, что было в модуле: горутины, мьютексы, семафор на канале, контекст с таймаутами и отменой, singleflight, TTL-кэш и дисциплина, при которой не утекает ни одна горутина.

Интернета в тестах нет: страницы «загружает» фейковый `Fetcher`, интерфейс которого объявлен в `types.go`.

```go
type Fetcher interface {
	Fetch(ctx context.Context, url string) (links []string, err error)
}
type Options struct {
	MaxDepth    int           // глубина (старт — 0); < 0 → 0
	Workers     int           // максимум одновременных Fetch; <= 0 → 1
	PageTimeout time.Duration // таймаут на один Fetch; 0 — без таймаута
}
type Result struct {
	Pages  map[string]int   // URL → минимальная глубина (только успешные)
	Errors map[string]error // URL → ошибка загрузки
}
```

## Часть 1. `Normalize(url string) string`

`Normalize` обрезает пробелы по краям и отбрасывает фрагмент, то есть всё, начиная с первого `#`. Например, `" a/b#top "` превращается в `"a/b"`, а `"#x"` — в `""`.

## Часть 2. `Crawl(ctx, f, start, opt) (*Result, error)`

`Crawl` обходит страницы в ширину, строго по уровням:

1. Уровень 0 — это `Normalize(start)`. Если старт пустой, возвращается пустой результат (карты не-nil) без ошибки.
2. Все URL текущего уровня загружаются параллельно, но одновременно выполняется не более `Workers` вызовов `Fetch`. Тест проверяет и сам лимит, и то, что он реально достигается.
3. Успешно загруженная страница попадает в `Pages[url] = depth`, а ошибка — в `Errors[url]`. Ссылки со страницы с ошибкой игнорируются, но обход продолжается.
4. Ссылки со страниц глубины `d < MaxDepth` нормализуются. Пустые и уже виденные ранее (на любом уровне) отбрасываются, а остальные образуют уровень `d+1`. Каждый URL загружается не более одного раза, даже если на него ссылается множество страниц и в графе есть циклы.
5. Если `PageTimeout > 0`, каждый `Fetch` получает `context.WithTimeout(ctx, PageTimeout)`. Таймаут одной страницы — это просто ошибка в `Errors`, а не повод останавливать обход.
6. При отмене `ctx` новые загрузки не запускаются, а уже запущенные дожидаются: они получили `ctx` и должны быстро завершиться. Функция возвращает частичный результат и `ctx.Err()`. После возврата не должно остаться ни одной горутины.

Почему обход идёт по уровням, а не по принципу «кто первый нашёл»? При полностью асинхронном обходе страницу могут сначала найти по длинному пути, и тогда её глубина окажется не минимальной, а её потомки выпадут за `MaxDepth`. Обход по уровням даёт детерминированный результат.

## Часть 3. `CachedFetcher`

`CachedFetcher` — обёртка над `Fetcher` с TTL-кэшем и защитой от cache stampede:

```go
type CachedFetcher struct {
	Fetcher Fetcher
	TTL     time.Duration    // <= 0 — не кэшировать
	Now     func() time.Time // nil → time.Now (в тестах — фейковые часы)
	// + приватные поля
}
func (c *CachedFetcher) Fetch(ctx context.Context, url string) ([]string, error)
```

Требования:

- Успешный результат хранится в кэше в течение `TTL`: запись валидна, пока выполняется $\mathrm{Now}() < t_\text{загрузки} + \mathrm{TTL}$. Ошибки не кэшируются.
- Одновременные запросы одного и того же URL приводят к одной загрузке (singleflight): 50 горутин дают ровно 1 вызов.
- Каждый ожидающий уважает свой собственный контекст. Если его отменили, он сразу возвращает `ctx.Err()`, а общая загрузка продолжается для остальных. Поэтому саму загрузку выполняйте в отдельной горутине с `context.WithoutCancel(ctx)`: значения контекста сохраняются, а отмена — нет.
- Возвращайте копию среза ссылок. Вызывающий может его изменить, и кэш от этого портиться не должен.
- `CachedFetcher` сам реализует `Fetcher`, поэтому его можно передать в `Crawl`, и тогда повторные обходы не ходят в «сеть».

## Подсказки

Семафор делается как `make(chan struct{}, workers)`. Перед захватом слота проверяйте `ctx.Err()`, ведь `select` выбирает среди готовых веток случайно.

Результаты, которые пишут горутины (`Pages`, `Errors`, найденные ссылки), защищайте мьютексом. А дедупликацию через `seen` удобно делать в основной горутине, после `wg.Wait()` для всего уровня.

`cancel()` от `WithTimeout` вызывайте сразу после `Fetch`, а не через `defer` в цикле, иначе контексты будут копиться до выхода из функции.

Загрузку, которая уже идёт (in-flight), удобно описать структурой `struct{ done chan struct{}; links []string; err error }`. Ожидающие делают `select { case <-fl.done: ...; case <-ctx.Done(): ... }`. Поля записываются до `close(done)`, а читаются после `<-done`, и это корректное отношение happens-before.
