# 02. ParallelMap с сохранением порядка (`parmap`)

Урок: [Горутины](../../lessons/02-goroutines.md)

Типичная ситуация: есть список URL, картинок или записей, и каждую нужно обработать долгой функцией. Хочется делать это параллельно, но так, чтобы результаты шли в том же порядке, что и вход, а паника в одном элементе не роняла весь процесс. Реализуйте обобщённую функцию:

```go
func Map[T, R any](in []T, workers int, f func(T) R) []R
```

Требования:

- `out[i] == f(in[i])`: порядок результатов совпадает с порядком входа, хотя сами элементы обрабатываются в произвольном порядке.
- Одновременно выполняется не более `workers` вызовов `f`; при `workers <= 0` берётся `runtime.GOMAXPROCS(0)`. Лишних горутин не запускайте, их должно быть `min(workers, len(in))`.
- Элементы раздаются воркерам динамически, через атомарный счётчик индекса или канал индексов. Так один медленный элемент не задерживает обработку целого чанка.
- Для пустого или `nil` входа возвращается пустой не-nil срез.
- Если `f` паникует в горутине-воркере, по умолчанию упадёт весь процесс, и `recover` в вызывающем коде эту панику не поймает. Поэтому `Map` должен перехватить панику внутри воркера, остановить раздачу новых элементов, дождаться всех воркеров и повторно запаниковать уже в вызывающей горутине с тем же значением (`panic(v)`).
- После возврата из `Map` (или паники) не должно остаться запущенных горутин.

Пример:

```go
parmap.Map([]int{1, 2, 3}, 2, func(x int) string { return strconv.Itoa(x * 10) })
// []string{"10", "20", "30"}
```

## Подсказки

Писать в `out[i]` из разных горутин безопасно: это разные элементы массива. А `wg.Wait()` устанавливает отношение happens-before между записями воркеров и чтением в вызывающей горутине, так что никакой дополнительной синхронизации для результатов не нужно.

Значение паники тоже передаётся через общую переменную, но её уже нужно защитить — `sync.Once` или мьютексом.

Для запуска воркеров удобен `for range workers` (Go 1.22+). И помните, что начиная с 1.22 переменная цикла своя на каждой итерации.
