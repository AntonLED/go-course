# 05. Pipeline: Generate → Square → Merge (`pipeline`)

Урок: [Concurrency в Go: каналы и паттерны](../../lessons/04-channels-patterns.md)

Конвейер из стадий, соединённых каналами, — один из самых узнаваемых паттернов Go. Написать его, чтобы он работал, несложно. Гораздо труднее сделать так, чтобы при отмене он не оставлял после себя повисших горутин, и именно это здесь проверяется. Реализуйте классический конвейер из статьи [Go Concurrency Patterns: Pipelines and cancellation](https://go.dev/blog/pipelines):

```go
func Generate(ctx context.Context, vals ...int) <-chan int            // генератор
func Square(ctx context.Context, in <-chan int) <-chan int            // стадия, порядок сохраняется
func Merge(ctx context.Context, ins ...<-chan int) <-chan int         // fan-in
func SquareParallel(ctx context.Context, in <-chan int, workers int) <-chan int // fan-out + fan-in
```

Правила:

1. Каждая функция сразу возвращает канал и запускает одну или несколько горутин, которые в него пишут.
2. Выходной канал закрывает тот, кто в него пишет, — ровно один раз и только когда писателей больше не осталось. `Merge` закрывает выход, когда закрыты все входы или отменён `ctx`. `Merge()` без аргументов возвращает уже закрытый канал.
3. Каждая блокирующая операция — и чтение из `in`, и запись в `out` — выполняется внутри `select` вместе с `<-ctx.Done()`. Тогда отмена контекста гарантированно освобождает все горутины, даже если:
   - потребитель перестал читать выход;
   - upstream-канал никогда не закрывается.
4. `SquareParallel` запускает `workers` стадий `Square` над одним и тем же входным каналом (fan-out; при `workers <= 0` запускается одна стадия) и объединяет их выходы через `Merge`. Порядок результатов не гарантируется.

Тесты проверяют корректность результатов, закрытие всех выходных каналов и отсутствие утечек горутин после отмены.

## Подсказки

Выход в `Merge` нужно закрывать в отдельной горутине, после `wg.Wait()`.

Возвращайте `<-chan int`, то есть канал только для чтения: тогда компилятор не позволит потребителю ни закрыть его, ни писать в него.
