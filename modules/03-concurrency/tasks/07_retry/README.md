# 07. Retry с экспоненциальным backoff и таймауты (`retry`)

Урок: [Контекст (Context)](../../lessons/05-context.md)

Сеть ненадёжна: запрос к соседнему сервису может упасть просто потому, что тот перезапускался. Поэтому клиенты повторяют запросы, но делают это с растущими паузами, чтобы не добить и без того перегруженный сервис, и умеют вовремя сдаться, если контекст отменён. В `types.go` уже есть `Policy`, `Permanent(err)` и `ErrExhausted`. Реализуйте в `retry.go`:

```go
func Backoff(p Policy, failed int) time.Duration
func Do(ctx context.Context, p Policy, f func(ctx context.Context) error) error
func DoWithTimeout[T any](ctx context.Context, d time.Duration, f func(ctx context.Context) (T, error)) (T, error)
```

## Backoff

`Backoff` возвращает паузу после `failed` неудачных попыток (`failed >= 1`):

$$
\text{pause} = \text{BaseDelay} \cdot \text{Multiplier}^{\,\text{failed} - 1}
$$

Если `MaxDelay > 0`, пауза не превышает `MaxDelay`. Значение `Multiplier <= 1` трактуется как 2. При `failed < 1` или `BaseDelay <= 0` результат равен 0.

Вычисление не должно переполняться: `Backoff(p, 500)` с потолком 50мс даёт 50мс, а без потолка — `math.MaxInt64`, но никак не отрицательное число.

## Do

| Ситуация | Результат |
|---|---|
| `ctx` уже отменён до первой попытки | `f` не вызывается, возвращается `ctx.Err()` |
| `f` вернула `nil` | `nil` |
| `f` вернула `Permanent(err)` | сразу `err` (без обёртки) |
| попытки кончились | ошибка, для которой верно и `errors.Is(err, ErrExhausted)`, и `errors.Is(err, last)` |
| `ctx` отменён во время паузы | немедленный возврат; `errors.Is` верно и для `ctx.Err()`, и для последней ошибки `f` |

Пауза между попытками обязана прерываться отменой контекста, поэтому `time.Sleep` здесь не подходит. Используйте `time.NewTimer` и `select` с `ctx.Done()`. Две ошибки сразу оборачиваются так: `fmt.Errorf("%w ...: %w", a, b)`.

## DoWithTimeout

`DoWithTimeout` выполняет `f` с контекстом `context.WithTimeout(ctx, d)`. Функция возвращается не позже, чем истечёт таймаут или отменится родительский контекст, даже если `f` контекст игнорирует. В этом случае результат — нулевое значение `T` и `ctx.Err()`. Горутина, в которой выполняется `f`, не должна утечь, когда `f` в конце концов завершится. Подсказка: подумайте о буфере у канала результата.

## Подсказки

Не забудьте `defer cancel()`: `go vet` (анализатор `lostcancel`) ругается на потерянный cancel.

В продакшене к паузе обычно добавляют jitter — случайную составляющую (`rand.Int64N`), чтобы клиенты не повторяли запросы синхронно. Здесь этого делать не нужно: тесты детерминированные.
