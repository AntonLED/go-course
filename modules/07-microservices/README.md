# Модуль 07. Основы микросервисов в Go

Пока программа живёт в одном процессе, вызов соседнего модуля — это просто вызов функции. Как только модули разъезжаются по разным сервисам, каждый такой вызов идёт по сети, а значит, может зависнуть, упасть или выполниться дважды. Этот модуль о том, как сервисы разговаривают друг с другом и как сделать этот разговор надёжным. Мы разберём таймауты, ретраи, идемпотентность и circuit breaker, а затем два протокола: JSON-RPC 2.0 и gRPC поверх protobuf, от спецификации до отдельных байтов на проводе.

Внешние библиотеки (grpc-go, protobuf) в курсе недоступны. Поэтому в уроках показан их настоящий API, а в задачах ключевые механизмы вы реализуете сами на стандартной библиотеке. Так даже полезнее: написав varint и фрейминг gRPC руками, вы будете точно знать, что делает библиотека за вас.

## Цели

После модуля вы будете:

- понимать компромиссы микросервисной архитектуры и знать основные паттерны устойчивости;
- уметь реализовать circuit breaker, retry с backoff и серверную идемпотентность;
- знать спецификацию JSON-RPC 2.0 и уметь написать для неё сервер и клиент;
- понимать wire format protobuf и то, как gRPC устроен поверх HTTP/2: фрейминг, статусы, дедлайны, мультиплексирование.

## Как проверять

Тесты запускайте с детектором гонок: в задачах много горутин, таймеров и конкурентного доступа. С тегом `solution` те же тесты прогоняются на эталонных решениях.

```bash
# ваше решение
go test -race ./modules/07-microservices/...
# эталоны
go test -race -tags solution ./modules/07-microservices/...
go vet ./modules/07-microservices/... && go vet -tags solution ./modules/07-microservices/...
```
