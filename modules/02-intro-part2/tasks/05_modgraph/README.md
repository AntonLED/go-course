# Задача 05. go.mod и Minimal Version Selection

Пакет `modgraph`. Команда `go build` каждый раз молча решает непростую задачу: по файлам `go.mod` всех зависимостей она определяет, какую версию каждого модуля взять. Давайте разберёмся, что именно она делает. Вы разберёте `go.mod`, посчитаете итоговый список версий алгоритмом MVS и ответите на вопрос «зачем нам этот модуль», как это делает `go mod why -m`.

Типы (`Module`, `Requirement`, `Replace`, `File`, `Graph`), ошибки `ErrSyntax` и `ErrNotRequired` и готовая функция `CompareVersions` лежат в `types.go`. Реализуйте в `modgraph.go`:

```go
func ParseGoMod(src string) (*File, error)
func BuildList(main Module, g Graph) []Module
func Why(main Module, g Graph, path string) ([]Module, error)
```

## ParseGoMod

Парсер должен понимать директивы `module` и `go` (однострочные), а также `require` и `replace` — и однострочные, и блоками `( ... )`. Директивы `toolchain` (однострочную), `exclude`, `retract` и `godebug` (в том числе блоками) нужно принять и проигнорировать. Комментарий `// indirect` помечает требование как косвенное.

Ошибки имеют вид `go.mod:<строка>: <описание>: <ErrSyntax>` и оборачивают `ErrSyntax` через `%w`. Для незакрытого блока указывается номер строки, где этот блок открыт.

```
replace github.com/a/lib => ../a-lib-fork                      // Old.Version == "" — все версии, New — локальный путь
replace github.com/b/lib/v2 v2.3.1 => github.com/me/b/v2 v2.3.2
```

## BuildList (MVS)

Обойдите все версии модулей, достижимые из `main`, и для каждого пути выберите максимальную из встреченных версий. Возьмём пример из статьи Russ Cox. Модуль A требует B1.2 и C1.2, B1.2 требует D1.3, C1.2 требует D1.4, а D1.3 и D1.4 оба требуют E1.2. Итоговый список: `A B@v1.2.0 C@v1.2.0 D@v1.4.0 E@v1.2.0`.

## Why

`Why` возвращает кратчайшую цепочку (ищите её обходом в ширину) от `main` до любой версии модуля `path`, включая оба конца.

## Подвохи

MVS учитывает требования и тех версий, которые в итоге не выбраны, если до них можно добраться. Поэтому `z` может остаться на `v1.9.0`, хотя выбранная `x v1.1.0` требует всего лишь `v1.1.0`.

Версии сравнивайте через `CompareVersions`, а не как строки: `v1.10.0 > v1.9.0`.

В графе бывают циклы и требования на главный модуль, и ваш код должен их пережить.

Запись `//indirect` без пробела — тоже indirect, так что сравнивайте текст комментария после `TrimSpace`.
