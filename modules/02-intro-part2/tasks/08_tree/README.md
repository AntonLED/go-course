# Задача 08. Итераторы по дереву и Pull-слияние

Пакет `tree`. Упорядоченная карта — вещь, которой в стандартной библиотеке Go нет, а нужна она постоянно: для диапазонных запросов, для вывода по порядку, для слияния отсортированных потоков. Здесь вы напишете её на основе обобщённого двоичного дерева поиска `Tree[K cmp.Ordered, V any]` (структура объявлена в `types.go`) и научите её отдавать данные через итераторы. Реализуйте в `tree.go`:

```go
func (t *Tree[K, V]) Put(k K, v V)
func (t *Tree[K, V]) Get(k K) (V, bool)
func (t *Tree[K, V]) Len() int
func (t *Tree[K, V]) All() iter.Seq2[K, V]            // in-order, по возрастанию
func (t *Tree[K, V]) Backward() iter.Seq2[K, V]       // по убыванию
func (t *Tree[K, V]) Keys() iter.Seq[K]
func (t *Tree[K, V]) Range(lo, hi K) iter.Seq2[K, V]  // lo <= k < hi
func MergeSorted[T cmp.Ordered](a, b iter.Seq[T]) iter.Seq[T]
```

Пример:

```go
var t tree.Tree[string, int]
t.Put("b", 2); t.Put("a", 1); t.Put("c", 3)
for k, v := range t.All() { fmt.Println(k, v) } // a 1, b 2, c 3

merged := tree.MergeSorted(t1.Keys(), t2.Keys()) // слияние двух отсортированных потоков
```

## Подвохи

Главная сложность — ранний выход из рекурсии. Рекурсивный обход дерева — это push-итератор, и когда `yield` вернул `false` где-то глубоко в рекурсии, об этом должны узнать все уровни выше. Типичная ошибка — игнорировать результат рекурсивного вызова: тогда после `break` обход продолжится, и рантайм упадёт с паникой. Идиоматичное решение укладывается в одну строку: `return n.left.walk(yield) && yield(n.key, n.val) && n.right.walk(yield)`.

`Range` не должен заходить в поддеревья за пределами диапазона: в левое — только если `lo < key`, в правое — только если `key < hi`. Граница `hi` не включается, а при `lo >= hi` результат пустой.

Если вставлять ключи в отсортированном порядке, дерево выродится в «палку» глубины $O(n)$. Стек горутины в Go растёт, так что рекурсия не упадёт, но `Put` и `Get` всё же лучше сделать итеративными: так и проще, и дешевле.

`MergeSorted` — классический случай для pull-итераторов (`iter.Pull`), потому что нужно попеременно тянуть элементы из двух источников. Не забудьте `defer stop()` для обоих: тест проверяет, что после `break` источники завершились. При равных элементах первым идёт элемент из `a`.
