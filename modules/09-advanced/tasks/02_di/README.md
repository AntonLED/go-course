# 02. Мини DI-контейнер на reflect (Provide / Invoke / Lifecycle)

Урок: [Внедрение зависимостей](../../lessons/02-di.md)

Когда в сервисе полсотни компонентов, ручная сборка в `main` превращается в длинную простыню, где легко перепутать порядок создания или забыть что-то закрыть при остановке. DI-контейнеры вроде `uber/dig` решают это так: вы регистрируете конструкторы, а контейнер сам по их сигнатурам выясняет, кого чем кормить. В этой задаче вы напишете упрощённый `uber/dig` плюс кусочек `fx.Lifecycle` для запуска и остановки. Типы `Hook`, `Lifecycle`, `Option`, `As` и ошибки уже есть в `types.go`.

```go
c := di.New()
c.Provide(NewConfig)                          // func() Config
c.Provide(NewDB)                              // func(Config) (*DB, error)
c.Provide(NewPgRepo, di.As(new(UserRepo)))    // func(*DB) *pgRepo, доступен и как UserRepo
c.Provide(NewService)                         // func(UserRepo, *DB) *Service
err := c.Invoke(func(s *Service) error { return s.Run() })
c.Start(ctx); defer c.Stop(ctx)
```

## Требования

### Provide(ctor, opts...)

- `ctor` должен быть функцией вида `func(deps...) T` или `func(deps...) (T, error)`. Если это не функция или nil, возвращается `ErrNotFunc`. Если сигнатура не подходит — ноль или больше двух результатов, второй результат не `error`, variadic-функция или `T == error`, — возвращается `ErrBadSignature`.
- Если тип уже зарегистрирован (в том числе встроенный `*Lifecycle`), возвращается `ErrDuplicate`.
- Опция `As(new(I))` дополнительно регистрирует значение под интерфейсом `I`. Если аргумент не указатель на интерфейс или `T` не реализует `I`, возвращается `ErrBadOption`. Регистрация атомарна: при любой ошибке не регистрируется ничего.
- В `Provide` конструктор не вызывается — контейнер ленивый.

### Invoke(fn)

- `fn` — функция, которая ничего не возвращает или возвращает `error`; иначе `ErrNotFunc` или `ErrBadSignature`. Ошибка, которую вернула `fn`, возвращается как есть.
- Аргументы разрешаются рекурсивно. Каждый конструктор вызывается не более одного раза (синглтон), и значение, зарегистрированное через `As`, — это тот же самый экземпляр.
- Если для типа нет провайдера, возвращается ошибка с `ErrMissing` и именем типа в виде `reflect.Type.String()`, например `*di.DB`.
- Цикл в зависимостях даёт `ErrCycle` с путём: `*di.A -> *di.B -> *di.C -> *di.A`.
- Ошибка конструктора оборачивается через `%w` и не кэшируется: следующий `Invoke` вызовет конструктор снова.
- Контейнер потокобезопасен: параллельные `Invoke` не создают второй экземпляр.

### Start / Stop

- Конструкторы получают `*Lifecycle` как обычную зависимость и регистрируют в нём `Hook`.
- `Start` вызывает `OnStart` в порядке регистрации. Он совпадает с порядком построения, то есть зависимости стартуют раньше зависимых. Если `OnStart` хука с номером $i$ упал, нужно вызвать `OnStop` у хуков $0 \ldots i-1$ в обратном порядке и вернуть ошибку через `errors.Join`.
- `Stop` вызывает `OnStop` у запущенных хуков в обратном порядке — у всех, даже если какие-то из них упали; ошибки объединяются. Повторный `Stop` ничего не делает.

## Подсказки

Из `reflect` вам понадобятся в основном `reflect.TypeFor[error]()`, `reflect.Type.Implements` и `reflect.Value.Call`.

Цикл удобно ловить, передавая в рекурсию стек типов, которые строятся прямо сейчас: если тип уже есть в стеке, вы нашли цикл, а сам стек и есть готовый путь для сообщения.

И не вызывайте пользовательскую функцию из `Invoke` под мьютексом контейнера — если она сама обратится к контейнеру, получится дедлок.
