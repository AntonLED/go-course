# 03. envconfig: заполнение структуры из переменных окружения

Урок: [Управление конфигурациями и средами](../../lessons/03-config.md) (и [Рефлексия](../../lessons/01-reflection.md))

В контейнере конфигурацию принято передавать через переменные окружения — так советует методология Twelve-Factor App. Читать их по одной через `os.Getenv`, парсить числа и длительности и подставлять значения по умолчанию быстро надоедает, поэтому в проектах используют библиотеки вроде `kelseyhightower/envconfig` или `cleanenv`: описываете структуру с тегами, и она заполняется сама. Здесь вы напишете такую библиотеку в миниатюре.

```go
func Load(dst any, lookup LookupFunc) error   // LookupFunc = func(string) (string, bool), как os.LookupEnv
```

```go
type Config struct {
    Port    int           `env:"PORT" default:"8080"`
    Timeout time.Duration `env:"TIMEOUT" default:"5s"`
    Hosts   []string      `env:"HOSTS" default:"a,b"`
    Level   slog.Level    `env:"LOG_LEVEL" default:"INFO"`  // encoding.TextUnmarshaler
    DB      DBConfig      `prefix:"DB_"`                    // DB_HOST, DB_PORT...
}
err := envconfig.Load(&cfg, os.LookupEnv)
```

Обратите внимание, что `Load` принимает функцию поиска, а не лезет в `os.Getenv` сама. Благодаря этому тесты подсовывают своё «окружение» и не трогают настоящее.

## Теги

| Тег | Смысл |
|---|---|
| `env:"NAME"` | имя переменной (с учётом префиксов вложенных структур) |
| `default:"v"` | используется, только если переменная не задана (`ok == false`); пустая, но заданная переменная — это значение `""` |
| `required:"true"` | ошибка `ErrRequired`, если итоговое значение пустое (не задана и нет default, или задана пустой) |
| `sep:";"` | разделитель элементов среза, по умолчанию `,`; элементы обрезаются `TrimSpace`; пустая строка → пустой не-nil срез |
| `prefix:"DB_"` | у поля-структуры без тега `env`: рекурсивно заполнить её, добавив префикс |

Если переменная не задана и default нет, поле не трогается и сохраняет прежнее значение. Так можно заполнить структуру значениями по умолчанию в коде, а окружением перекрыть только часть из них.

## Поддерживаемые типы

`Load` умеет заполнять поля следующих типов:

- `string` и `bool`;
- все `int*` и `uint*` с проверкой переполнения: `"300"` в `int8` — ошибка;
- `float32` и `float64`;
- `time.Duration` через `time.ParseDuration`;
- срезы перечисленных типов и указатели на них (память под значение выделяется);
- любой тип, у которого `*T` реализует `encoding.TextUnmarshaler`. Эту проверку нужно делать раньше, чем разбор по `Kind`.

Для всех остальных типов возвращается `ErrUnsupported`.

## Ошибки

- Если `dst` — не ненулевой указатель на структуру, возвращается `ErrInvalidTarget`.
- Ошибки отдельных полей оборачиваются в `*FieldError{Field: "DB.Port", Key: "DB_PORT", Err: ...}` и собираются все сразу через `errors.Join`, а корректные поля при этом заполняются. Человеку, который чинит конфиг, гораздо удобнее увидеть весь список проблем, чем исправлять их по одной.
- Неэкспортируемые поля и поля без тега `env` игнорируются.

## Подсказки

У `time.Duration` `Kind() == Int64`, поэтому, если сначала смотреть на `Kind`, строка `"5s"` пойдёт в `strconv.ParseInt` и сломается. Проверяйте конкретный тип раньше.

Проверить, реализует ли тип `TextUnmarshaler`, можно через `reflect.PointerTo(t).Implements(...)`, а получить сам интерфейс — через `v.Addr().Interface()`.

Для целых чисел удобно `strconv.ParseInt(raw, 10, t.Bits())`: третий аргумент сам проверит переполнение для нужной разрядности.
