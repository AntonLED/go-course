# 07. Свой slog.Handler: JSON + маскирование секретов

Урок: [Логгирование, трейсинг, метрики](../../lessons/06-observability.md)

Рано или поздно в логах любого сервиса оказывается пароль: кто-то залогировал запрос целиком, и `password` уехал в Elasticsearch, где его видит половина компании. Надёжнее всего ловить такие вещи на уровне хендлера, через который проходят все записи. В этой задаче вы реализуете `slog.Handler`, который пишет по одной JSON-строке на запись и маскирует значения «секретных» ключей. Проверяется он в том числе официальным `testing/slogtest.TestHandler` — тем же набором тестов, которым проверяют хендлеры стандартной библиотеки.

```go
h := redact.NewHandler(os.Stdout, &redact.Options{Level: slog.LevelDebug})
log := slog.New(h).With("svc", "api")
log.Info("login", "user", "bob", "password", "hunter2")
// {"time":"...","level":"INFO","msg":"login","svc":"api","user":"bob","password":"[REDACTED]"}
```

## Формат

Ключи идут в таком порядке: сначала `time` в формате RFC3339Nano (если `r.Time.IsZero()`, ключа `time` нет вовсе), затем `level` (`r.Level.String()`), затем `msg`. После них — атрибуты из `WithAttrs`/`WithGroup` и из самой записи, в порядке добавления.

Значения кодируются так:

- строки, `bool` и числа как есть; `int64`, `uint64` и `float64` становятся JSON-числами, а `NaN` и `±Inf` — строками;
- `time.Duration` — строкой вида `"1.5s"`;
- `time.Time` — в RFC3339Nano;
- `error` — через `err.Error()`;
- прочие значения `Any` — через `json.Marshal`, а если он вернул ошибку — через `fmt.Sprint`.

Группы превращаются во вложенные объекты. Группа с пустым ключом встраивается в текущий уровень, пустая группа не выводится. `WithGroup("g")`, после которого не было ни одного атрибута, не должен выводить `"g":{}`.

Пустой атрибут (`slog.Attr{}`) игнорируется. Значения `LogValuer` разрешаются через `Value.Resolve()` — в том числе внутри групп и в `WithAttrs`.

## Маскирование

Значение заменяется на `"[REDACTED]"`, если ключ входит в `Options.RedactKeys`. Сравнение идёт без учёта регистра, а `nil` означает `DefaultRedactKeys`. Маскирование работает на любом уровне вложенности и для атрибутов из `WithAttrs`. Если секретным оказался ключ группы, маскируется вся группа целиком.

Секрет внутри `LogValuer` тоже должен маскироваться. Для этого сначала вызывайте `Resolve`, а уже потом проверяйте ключи.

## Прочее

`Options.Level` (при `nil` — `Info`) читается заново при каждом вызове `Enabled`. Благодаря этому `slog.LevelVar` может менять уровень логирования на лету.

`WithAttrs` и `WithGroup` возвращают новый хендлер и не меняют исходный, а потомки одного хендлера независимы друг от друга. Здесь легко ошибиться с `append` к общему срезу: два потомка допишут свои атрибуты в один и тот же массив и затрут друг друга.

Хендлер потокобезопасен: на каждую строку приходится ровно один вызов `w.Write` под мьютексом, общим для всех производных хендлеров. Если у каждого потомка будет свой мьютекс, строки от разных логгеров перемешаются в одном writer'е.

## Подсказки

Прочитайте [slog handler guide](https://github.com/golang/example/blob/master/slog-handler-guide/README.md). Подход, где хендлер копит список groupOrAttrs и применяет его только в `Handle`, — самый простой способ правильно выбросить пустые группы.
