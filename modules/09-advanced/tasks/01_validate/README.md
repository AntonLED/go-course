# 01. Валидатор структур по тегам (reflect)

Урок: [Рефлексия](../../lessons/01-reflection.md)

Почти каждый HTTP-обработчик начинается с проверки входных данных: имя не пустое, email похож на email, в заказе есть хотя бы одна позиция. Писать эти `if` руками для каждой структуры утомительно, поэтому в Go-проектах обычно берут `go-playground/validator`, который читает правила из тегов полей. В этой задаче вы напишете его мини-аналог на пакете `reflect`.

```go
func Validate(v any) error
```

На вход `Validate` принимает структуру или ненулевой указатель на структуру. Для любого другого значения она возвращает ошибку `ErrNotStruct`.

## Правила тега `validate:"..."`

Правила перечисляются через запятую и проверяются по порядку. Для каждого поля записывается только первое нарушенное правило — сообщать «имя слишком короткое» вслед за «имя обязательно» бессмысленно.

| Правило | Смысл |
|---|---|
| `required` | значение не нулевое; для строк, срезов, map — `len > 0`; указатель не `nil` |
| `omitempty` | если значение пустое (в смысле `required`) — остальные правила поля не применяются |
| `min=N`, `max=N` | строки — длина в рунах; срезы/массивы/map — `len`; числа — значение |
| `email` | только для строк: ровно одна `@`, непустая локальная часть, в домене есть `.` не по краям, без `..`, без пробельных символов |
| `oneof=a b c` | строка (или целое число) равна одному из вариантов через пробел |
| `-` (весь тег) | поле пропускается |

Дополнительные требования:

- Неэкспортируемые поля игнорируются.
- `min`, `max`, `email` и `oneof` применяются к значению под указателем. `nil`-указатель без `required` не проверяется.
- Вложенные структуры, указатели на структуры и элементы срезов структур проверяются рекурсивно, независимо от правил самого поля. Пути к полям записываются так: `Address.City`, `Billing.Zip`, `Items[1].SKU`.
- Неизвестное правило, нечисловой параметр у `min`/`max`, `min` на `bool` или `email` на `int` — это ошибка программиста, а не пользователя. В таком случае верните ошибку, оборачивающую `ErrBadTag` (`fmt.Errorf("%w: ...", ErrBadTag, ...)`), а не `ValidationErrors`.

Если нарушения найдены, результатом будет `ValidationErrors` — тип-срез `[]FieldError`, объявленный в `types.go`.

```go
type User struct {
    Name  string `validate:"required,min=3,max=10"`
    Email string `validate:"required,email"`
    Items []Item `validate:"min=1"`
}
err := Validate(User{Name: "Юл", Email: "a@b"})
// ValidationErrors{{"Name","min","3"}, {"Email","email",""}, {"Items","min","1"}}
```

## Подвохи

Длину строки для `min` и `max` считайте в рунах: `len("Юл") == 4`, а рун в нём всего 2.

`reflect.Value.Interface()` паникует на неэкспортируемых полях, так что пропускайте их до того, как полезете за значением.

Ошибки должны идти в порядке объявления полей, то есть в порядке обхода в глубину.

## Бонус

Разбор тегов на каждый вызов — лишняя работа, ведь у одного типа они не меняются. Закэшируйте разобранные теги по `reflect.Type` в `sync.Map` и сравните результат бенчмарка `BenchmarkValidate` до и после.
