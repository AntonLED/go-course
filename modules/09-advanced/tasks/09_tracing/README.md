# 09. Трейсинг: W3C traceparent, пропагация, span-дерево

Урок: [Логгирование, трейсинг, метрики](../../lessons/06-observability.md)

Когда запрос пользователя проходит через пять сервисов и где-то по дороге тормозит, логи каждого сервиса по отдельности мало что объясняют. Распределённый трейсинг связывает их: каждый сервис передаёт следующему идентификатор трассы в заголовке `traceparent`, а из собранных спанов потом строится дерево вызовов. В этой задаче вы напишете мини-OpenTelemetry на стандартной библиотеке. Типы `TraceID`, `SpanID`, `SpanContext` и `SpanData` уже есть в `types.go`.

## 1. `ParseTraceparent` / `SpanContext.Traceparent`
```
traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
             ^^ ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ ^^^^^^^^^^^^^^^^ ^^
          version        trace-id (16 байт)      parent-id (8 б) flags
```

Правила разбора взяты из [спецификации](https://www.w3.org/TR/trace-context/#traceparent-header):

- все поля записаны строчным hex, разделители `-` стоят на позициях 2, 35 и 52;
- версия `ff` запрещена; у версии `00` длина заголовка ровно 55 символов, а у будущих версий допускается хвост, но символ 55 обязан быть `-`;
- trace-id и parent-id из одних нулей недопустимы;
- `Sampled = flags & 0x01`, остальные биты флагов игнорируются.

Любое нарушение даёт `ErrInvalidTraceparent`. Обратная функция `Traceparent()` всегда генерирует версию `00` и флаги `01` или `00`.

## 2. `Tracer`, `Span`

`NewTracer(rnd io.Reader)` принимает источник случайности для идентификаторов; при `nil` используется `crypto/rand`. Нулевой ID недопустим, поэтому, если генератор выдал нули, сгенерируйте ID заново.

`Start(ctx, name)` ищет родителя в таком порядке: сначала спан из `ctx`; если его нет — удалённый `SpanContext` из `ctx`, положенный туда через `ContextWithRemote` (у него `Remote=true`); если нет и его — начинается новая трасса с `Sampled=true`. `TraceID` и `Sampled` наследуются от родителя, а `SpanID` всегда новый. `Start` возвращает `ctx` с новым спаном.

`SetAttr` добавляет атрибут, но после `End` игнорируется. `End` идемпотентен и добавляет `SpanData` в `Finished()`.

`Finished()` возвращает копию (включая `Attrs`) в порядке завершения спанов. Всё это должно быть потокобезопасным.

## 3. Пропагация

`Inject(ctx, h)` записывает в заголовки `traceparent` текущего спана, а если его нет — удалённого контекста. Если нет ни того, ни другого, ничего не пишется.

`Extract(ctx, h)` кладёт валидный заголовок в ctx как удалённый контекст. Невалидный заголовок просто игнорируется: начинается новая трасса, а не ответ 400. Трейсинг — вспомогательная подсистема, и из-за кривого заголовка от чужого клиента запрос падать не должен.

`Middleware(tr, next)` вызывает `Extract`, затем открывает спан `"METHOD /path"` с атрибутами `http.method`, `http.path` и `http.status_code` и после обработчика вызывает `End`. Чтобы узнать статус, перехватите `WriteHeader` и `Write`; если обработчик ничего не написал, статус — `200`.

## 4. `Tree(spans)`
```
GET /outer
  a.call-b
    GET /inner
      b.db
```

`Tree` выводит по строке на спан с отступом в 2 пробела на уровень вложенности. Корнями считаются спаны без родителя и спаны, чей родитель не входит в набор (например, удалённый). Соседи сортируются по `Start`, а при равенстве — по `Name`. Для пустого входа возвращается `""`.
