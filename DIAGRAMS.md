# Схемы в курсе: как рисовать

Схемы — это SVG-файлы, нарисованные вручную, рядом с уроком: `modules/NN-*/lessons/img/<имя>.svg`.
В markdown урока они вставляются отдельной строкой:

```md
![Подпись: что показывает схема (можно с `кодом`)](img/slice-sharing.svg)
```

Генератор книги (`book/gen.mjs`) встраивает SVG прямо в страницу внутри `<figure>`, подпись становится `<figcaption>`.
Поэтому `currentColor` берёт цвет текста темы, и схема сама переключается между светлой и тёмной темой.
На GitHub и в обычном просмотрщике markdown та же строка покажется как обычная картинка.

Образец качества: `modules/01-intro-part1/lessons/img/slice-sharing.svg` (и как он встроен в `03-slices.md`).

## Что рисовать

Рисуем **механизм**, а не его название. Схема оправдана, когда читатель видит то, что иначе пришлось бы собирать в голове из текста:
куда идут данные, кто с кем говорит, что лежит в памяти и куда указывает, через какие состояния проходит объект, что меняется между «до» и «после».
Если то же самое быстрее сказать одним предложением — схема не нужна.

Хорошие кандидаты: раскладка в памяти (заголовки, указатели, бакеты, itab), машины состояний, диаграммы последовательности (handshake, протоколы, flow),
конвейеры и fan-in/out, деревья (контекстов, вызовов, цепочек сертификатов), временные шкалы (таймауты, backoff, GC-фазы), сравнение двух вариантов бок о бок.

Подписывай стрелки (`writes`, `ptr`, `ClientHello`, `cancel()`), а не оставляй «как-то связано».
Схема должна быть **фактически точной** — это учебник: имена полей, порядок сообщений, числа должны совпадать с текстом урока и с реальностью.

## Технические правила

- Корень: `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 W H" role="img" aria-label="…" font-family="ui-sans-serif, system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif" font-size="13" fill="currentColor">` + `<title>`.
  Ширина `W` ≈ 640–720 (колонка книги ~650px, так текст будет ~1:1). Высоту подбирай по содержимому, без пустых полей.
- **Никаких** `<style>`, `<script>`, `<foreignObject>`, внешних картинок и шрифтов, `width`/`height` на корне (только `viewBox`).
- Цвета:
  - основной текст, линии, стрелки — `currentColor`; второстепенное — `currentColor` с `opacity="0.6"`;
  - акцент (то, о чём схема): `#0891b2` (бирюза); «хорошо/успех»: `#16a34a`; «плохо/ошибка/гонка»: `#dc2626`; «внимание/ожидание»: `#d97706`; ещё один различимый: `#7c3aed`.
    Эти цвета читаются и на светлом, и на тёмном фоне. Заливки — тот же цвет с `fill-opacity="0.12"`–`0.18`.
  - Не используй белый/чёрный литералом: фон у схемы прозрачный, тема может быть любой.
- Моноширинный шрифт для кода и идентификаторов: `font-family="ui-monospace, SFMono-Regular, Menlo, monospace"`, размер 12.
  Размер текста 11–13. Подписи короткие (1–4 слова); объяснение — в подписи под схемой.
- Стрелки — через `<defs><marker>` (см. образец: `markerUnits="userSpaceOnUse"`, `orient="auto"`); для цветной стрелки — отдельный marker с тем же цветом. id внутри файла любые — генератор сам добавляет им префикс.
- Выравнивай по сетке (шаг 4 или 8), одинаковые отступы, общие базовые линии. Стрелки не должны пересекать текст.
- Текст внутри `<text>` экранируй: `&lt;` `&gt;` `&amp;`. Пустые строки внутри SVG допустимы (генератор их удаляет).

## Проверка (обязательно для каждой схемы)

```bash
cd go-course
NODE_PATH=$(npm root -g) node book/tools/render-svg.cjs modules/NN-*/lessons/img/x.svg /tmp/x   # → /tmp/x-light.png, /tmp/x-dark.png
```

Открой **оба** PNG и посмотри глазами: ничего не наезжает, текст не обрезан, стрелки указывают куда надо, читается в обеих темах.
Затем `node book/gen.mjs` — он упадёт, если файл схемы не найден.
