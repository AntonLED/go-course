# Соглашения по структуре курса (для авторов)

Модуль Go: `gocourse` (корень репозитория, `go.mod` с `go 1.23`). **Только стандартная библиотека** — внешних зависимостей нет и не будет (нет доступа к proxy.golang.org). НЕ меняй `go.mod`.

Целевая версия API — **Go 1.23**. Нельзя: `testing.B.Loop`, `t.Context()`, `strings.Lines/SplitSeq/FieldsSeq`, `bytes.Lines`, `os.Root`, `weak`, `encoding/json` `omitzero`, `crypto/*` из 1.24 (hkdf, sha3, mlkem). Можно: generics, `iter`, range-over-func, `slices`, `maps`, `min/max/clear`, `log/slog`, `net/http` ServeMux-паттерны (`"GET /items/{id}"`), `r.PathValue`, `errors.Join`, `context.WithoutCancel/AfterFunc`, `sync.OnceValue`, `unique`.

## Раскладка модуля

```
modules/NN-slug/
  README.md                 # обзор модуля: цели, список уроков (ссылки), список задач, как проверять
  lessons/
    01-<slug>.md            # конспект урока (по-русски), 1 файл на урок из силлабуса, кроме «Задание N»
  tasks/
    01_<slug>/              # 1–2 задачи на урок + финальная задача «Задание N» (последняя, самая большая)
      README.md             # условие: что сделать, сигнатуры, примеры, подсказки, «запуск проверки»
      <name>.go             # ЗАГОТОВКА: первая строка `//go:build !solution`
      <name>_solution.go    # ЭТАЛОН:    первая строка `//go:build solution`
      <name>_test.go        # тесты БЕЗ build-тега, проверяют публичный API
  quiz.json                 # тест для веб-морды (формат ниже)
```

- Имя пакета задачи — короткое, lowercase, без подчёркиваний (например `wordfreq`). Директория может отличаться (`03_wordfreq`).
- Финальная задача модуля называется `NN_project_<slug>` (где NN — последний номер), в README пишется «Задание N».
- Заготовка ОБЯЗАНА компилироваться (`go vet ./...` чисто) и ОБЯЗАНА проваливать тесты (обычно `panic("TODO")` или возврат нулевых значений). Оставь в заготовке полезные комментарии/типы/сигнатуры, но не решение.
- Эталон — идиоматичный, чистый, с комментариями в ключевых местах.
- Всё, что нужно и заготовке, и эталону (общие типы, ошибки-сентинелы), можно вынести в третий файл без тега (например `types.go`) — тогда не дублируй в stub/solution.
- Тесты: детерминированные, быстрые (< 3 с на пакет), без интернета (localhost/`httptest`/`net.Pipe` — можно), проходят под `-race`. Используй табличные тесты и `t.Run`, понятные сообщения об ошибках на русском (`t.Errorf("Reverse(%q) = %q, ожидалось %q", ...)`). Для конкурентности — проверки на гонки/утечки/таймауты с разумными порогами (не флаки!).
- Где уместно — бенчмарки `BenchmarkXxx` (через `for i := 0; i < b.N; i++`).
- Уровень: от junior до крепкого middle. Хорошо, если в каждой задаче есть «подвох» (граничные случаи, unicode, nil, закрытые каналы, отмена контекста и т.п.).

## Проверка (обязательно прогони сам)

```
cd go-course
GOTOOLCHAIN=local go vet ./modules/NN-slug/...                     # заготовки компилируются
GOTOOLCHAIN=local go vet -tags solution ./modules/NN-slug/...
GOTOOLCHAIN=local go test -race -count=1 -tags solution ./modules/NN-slug/...   # эталоны ЗЕЛЁНЫЕ
GOTOOLCHAIN=local go test -count=1 ./modules/NN-slug/...           # заготовки КРАСНЫЕ (каждый пакет FAIL)
```
Прогони эталонные тесты `-count=3`, чтобы убедиться в отсутствии флаков.

## Конспекты уроков (lessons/*.md)

По-русски, плотно и по делу: ключевые идеи, примеры кода, «как это устроено внутри» (где уместно — runtime/память), типичные ошибки и подводные камни, вопросы с собеседований, ссылки на официальную документацию (go.dev/ref/spec, pkg.go.dev, go.dev/blog). 100–250 строк на урок. В конце — «Практика: задачи X, Y» со ссылками на директории задач.

## Формат quiz.json

```json
{
  "module": "01",
  "title": "Введение в Go. Часть 1",
  "questions": [
    {
      "id": "01-001",
      "lesson": "Работа с массивами и срезами",
      "type": "single",
      "q": "Что выведет программа?",
      "code": "package main\n...",
      "options": ["[1 2 3]", "[1 2]", "panic"],
      "answer": [0],
      "explain": "Почему так (1–3 предложения)."
    },
    { "type": "multi",  "...": "answer — массив индексов всех верных вариантов" },
    { "type": "input",  "q": "Что напечатает ...?", "answer": "3 5", "accept": ["3  5"], "explain": "..." }
  ]
}
```
- `lesson` — точное название урока из силлабуса. `code` — необязательный.
- Для `input` сравнение идёт после trim и схлопывания пробелов, без учёта регистра; `accept` — альтернативные ответы.
- 4–6 вопросов на урок, итого 25–40 на модуль. Много вопросов «что выведет код», хитрые случаи (append и общий backing array, nil-интерфейс, замыкания в циклах до/после 1.22, порядок defer, deadlock, select, map-итерация и т.п.). Варианты ответов правдоподобные. `id` уникальные: `NN-001`…
- Валидный JSON (проверь `python3 -m json.tool`).

04-data «Работа с данными»: Работа с потоками ввода/вывода; Работа с аргументами командной строки; Работа с файлами; Работа с JSON, YAML; Работа с SQL базами данных; Задание 4
05-web «Веб-разработка на Go»: Основы HTTP и запуск сервера в Go; Роутинг и middleware; Работа с запросами и ответами; Шаблоны и статические файлы; HTTP-клиент в Go; Популярные фреймворки для HTTP; Задание 5
06-testing «Тестирование и отладка»: Тестирование в Go; Мокирование и тестирование API; Бенчмарки; Профилирование; Задание 6
07-microservices «Основы микросервисов в Go»: Введение в микросервисы; JSON-RPC; gRPC + protobuf; Задание 7
08-security «Вопросы безопасности»: TLS, Сертификаты, Цепочки сертификатов; Безопасность в HTTP (HTTPS); Безопасность в gRPC; Аутентификация и авторизация (JWT); Аутентификация и авторизация (OAuth 2.0); Задание 8
