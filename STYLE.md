# Как писать текст курса

Курс читает живой человек, который готовится к работе на Go. Текст должен звучать так, будто его написал опытный инженер-преподаватель, а не сгенерировала модель. Хорошие ориентиры по интонации — «The Rust Programming Language», «Go by Example», статьи в go.dev/blog, лучшие русские лекции.

## Что выдаёт «машинный» текст (так НЕ пишем)

- **Телеграфный стиль.** Сплошные списки из обрывков фраз вместо объяснения: «Отмена — каскадно вниз. Потомок — не влияет.» Мысль разорвана, связи между фактами нет.
- **Жирный через слово**, КАПС для выразительности («ВСЕГДА», «ПРИЧИНА»), восклицательные знаки.
- **Тире вместо глаголов**: «`X` — это Y — поэтому Z — важно». Одно-два тире на абзац — нормально, цепочки — нет.
- **Стрелки в тексте** (`→`, `⇒`) вместо слов «поэтому», «превращается в», «затем». В таблицах и схемах стрелки допустимы.
- **Шаблонные рубрики и шаблонные связки**: «Важно отметить, что», «Стоит подчеркнуть», «Ключевой момент:», «Итак, подведём итоги», «В современном мире», «является неотъемлемой частью».
- **Однообразный ритм**: каждое предложение одной длины и одной конструкции; каждый раздел — «определение → список → подводные камни → вопросы».
- **Пересказ очевидного** и вода. Мы не пишем «функция `len` возвращает длину, что позволяет узнать длину».

## Как пишем

- **Объясняем, а не перечисляем.** Сначала зачем это нужно (задача, боль, пример из жизни), потом как устроено, потом где споткнётесь. Факты связаны словами «потому что», «поэтому», «но», «а значит».
- **Абзацы прозы — основа.** Списки оставляем там, где это действительно список однородных вещей (флаги, поля, шаги алгоритма, варианты). Короткий пункт списка — нормально; список из 12 пунктов с тремя фактами в каждом — нет, это абзацы.
- **Обращаемся к читателю** на «вы» или пишем от «мы» («давайте посмотрим», «обратите внимание», «вы наверняка встречали»), но без заигрывания и без шуток через строчку.
- **Разный ритм.** Короткое предложение после длинного. Иногда вопрос, на который следующий абзац отвечает.
- **Точность важнее красоты.** Ни один технический факт, число, версия Go или имя API не должны потеряться или исказиться при переписывании.
- **Жирный** — только для термина в момент его определения или одной действительно критичной мысли на раздел.
- Русская типографика: «ёлочки», длинное тире с пробелами, `...` не используем (есть «…»), неразрывные пробелы не нужны.

## Формулы — только LaTeX

Книга рендерит формулы KaTeX: `$...$` внутри строки, `$$...$$` отдельным блоком (каждый `$$` на своей строке).
Всё, что является математической записью, пишем в LaTeX:

| было | стало |
|---|---|
| `O(n²)`, O(n log n) | `$O(n^2)$`, `$O(n \log n)$` |
| S(N) = 1 / ((1−p) + p/N) | `$$`<br>`S(N) = \dfrac{1}{(1-p) + \dfrac{p}{N}}`<br>`$$` |
| 0.999³ ≈ 99.7% | `$0.999^3 \approx 99.7\%$` |
| base·2ⁿ, ≤, ≥, ≠, ×, √ | `$\text{base} \cdot 2^n$`, `\le`, `\ge`, `\ne`, `\times`, `\sqrt{}` |
| цель кучи = live × (1 + GOGC/100) | `$H_\text{goal} = H_\text{live} \cdot \left(1 + \frac{\mathrm{GOGC}}{100}\right)$` |
| 2^29 − 1, 10⁹ | `$2^{29} - 1$`, `$10^9$` |

Правила:
- Код остаётся кодом: выражения Go (`n<<3 | wt`, `len(s)*2`, `x >> 63`) — в обратных кавычках, это не формулы. Формулой делаем то, что описывает математику (сложность, законы, оценки, вероятности, формулы из спецификаций). Если в тексте формула из спецификации записана кодом и там же объясняется её смысл — можно дать и то и другое.
- Внутри формул русский текст — через `\text{...}`.
- Любой **обычный символ `$`** вне формул (переменные окружения `$GOPATH`, плейсхолдеры `$1`, цены) обязан быть внутри обратных кавычек `` `$GOPATH` ``, иначе KaTeX примет его за начало формулы.
- Внутри блоков кода ```` ``` ```` и SVG-схем ничего не меняем.
- Для дробей внутри строки лучше `\tfrac` или `a/b`, чтобы не растягивать межстрочный интервал; `\dfrac` — в блочных формулах.

## Чего нельзя трогать при правке

- Блоки кода ```` ``` ```` — побайтно без изменений (включая комментарии в них).
- Строки схем `![подпись](img/файл.svg)` — путь и сама строка остаются на месте (подпись можно сделать человечнее, путь — нет).
- Ссылки (цели ссылок), заголовки-якоря, на которые ссылаются другие файлы, названия задач и директорий.
- В README задач — требования, сигнатуры, граничные случаи, коды ошибок, числа: это спецификация, по ней написаны тесты. Меняется только подача.
